5. Темы: Белые Нити и Бриллиант Ремонт — тёмные премиальные, ДезГарант — светлая «чистая» (§3.4).

## 1. Архитектура: один репозиторий, один Vercel-проект, три хоста

### 1.1 Хосты и роутинг

Публичные URL всех трёх сайтов чистые (без префиксов). Middleware по заголовку Host переписывает запрос во внутренний маршрут `/_sites/<site>/...`. Три сайта живут в явных папках (они структурно разные), а не в динамическом сегменте.

| site | бренд | будущие домены (не куплены; имена — предложение) | хосты сейчас | dev |
|---|---|---|---|---|
| `belye-niti` | ООО «Белые Нити» | `belye-niti.ru`, `www.belye-niti.ru` | `belye-niti.vercel.app` | `localhost:3000` |
| `dezgarant` | ДезГарант | `dezgarant56.ru`, `www.…` | `dezgarant56.vercel.app` | `dezgarant.localhost:3000` |
| `remont` | Бриллиант Ремонт | `brilliant-remont56.ru`, `www.…` | `brilliant-remont56.vercel.app` | `remont.localhost:3000` |

Реализация роутинга — два варианта, выбрать A, если он проходит e2e; иначе B:
- **A (предпочтительно, без вызова функции на каждый запрос)**: `rewrites()` в `next.config.ts` с условиями `has` — сначала по `host` каждого бренда (`{ type: 'host', value: 'dezgarant56.vercel.app' }` → `/_sites/dezgarant/:path*`), затем по `query` `site` и по `cookie` `site` (для preview-хостов), последним — безусловный fallback на `/_sites/belye-niti/:path*`; `source` с regex-исключением `/:path((?!api/|_next/|brands/|fonts/).*)`. Cookie ставит крошечный Route Handler `GET /api/site?to=<site>` (Set-Cookie + redirect на `/`), на него ведут кросс-брендовые ссылки зонтика на preview-хостах. Страницы остаются статическими, роутинг решается на уровне Edge Network Vercel.
- **B (резерв)**: `proxy.ts` в корне (в Next 16 это замена middleware; работает только на Node-рантайме, runtime не настраивается) с `export function proxy(request)` и `config.matcher = ['/((?!api|_next/static|_next/image|brands|fonts|favicon.ico).*)']`; перед установкой своих заголовков вычищать входящие (`x-site`), чтобы бренд нельзя было подделать.

Общие правила для обоих вариантов:
1. `resolveSiteByHost(host)` — чистая функция из `lib/site.ts` (host без порта, `www.` отбрасывается), покрыта `node --test`.
2. Хосты `*.vercel.app`, не входящие в карту (автоматические preview-URL вида `belye-niti-git-*.vercel.app`), → сайт из `?site=` / cookie `site`, иначе `belye-niti`; так владелец смотрит все три сайта на любом preview-деплое. Любой другой неизвестный хост (чужой домен, направленный на проект) → тоже зонтик, но с `noindex` — не 404, чтобы не ломать будущие домены до правки карты.
3. Rewrite: `/${path}` → `/_sites/${site}${path}`; в варианте B — заголовок `x-site` в ответ для отладки.
4. Matcher исключает `/_next`, `/api`, `/brands` (публичные файлы брендов), `/fonts`. `/robots.txt` и `/sitemap.xml` НЕ исключать — они per-host (см. §9).
5. Прямой заход на `/_sites/*` не блокировать (там же лежат OG-изображения), но в robots — `Disallow: /_sites/`.
6. Кросс-брендовые ссылки (зонтик → бренд): `siteUrl('dezgarant')` = `NEXT_PUBLIC_URL_DEZGARANT`, если задан; иначе `?site=dezgarant` на текущем хосте. Внутри бренда все ссылки обычные (`/uslugi/klopy`).
7. Canonical: `SITES[site].canonical` (env). До покупки доменов — vercel.app-хост бренда.

### 1.3 `config/sites.ts`

Один объект `SITES` с полями: `id`, `name`, `shortName`, `slogan`, `hosts: string[]`, `canonical`, `theme: 'dark' | 'light'`, `accent: 'red' | 'teal'`, `ymId` (из `NEXT_PUBLIC_YM_<SITE>`), `telegramChatEnv`, `leadEmailEnv`, `nav: {href,label}[]`. Новое направление = новая запись + папка в `app/_sites/` + файлы в `content/` — это и есть «зонтичность» из брифа владельца.

## 2. Стек (точный)

1. Next.js 16.3.x (latest на 11.09.2026 — 16.3.4) через `create-next-app` (App Router, TypeScript, Tailwind CSS v4, ESLint flat config, `src/` не использовать, import alias `@/*`). Особенности 16: Turbopack по умолчанию (кастомный webpack-конфиг не заводить), `proxy.ts` вместо middleware, `cookies()/headers()/params` только через `await`, команда `next lint` удалена — в скриптах `eslint .`, `images.remotePatterns` вместо `domains`, Node.js ≥ 20.9, TypeScript ≥ 5.1. Точные версии зафиксировать в `package.json` при bootstrap.
2. React текущий из шаблона; клиентские компоненты только там, где есть интерактив (формы, калькуляторы, слайдер, меню).
3. Tailwind CSS 4.3.x: `@import "tailwindcss"` + токены через `@theme` в `globals.css`, плагин `@tailwindcss/postcss`, без `tailwind.config`, без autoprefixer/postcss-import. Шрифтовые переменные из `next/font` подключаются через `@theme { --font-display: var(--font-display) }`. Утилиты + небольшой слой компонентных классов.
4. Шрифты через `next/font/google` с `subsets: ['cyrillic','latin']` и `variable` (вариативные, без `weight`; файлы скачиваются при сборке и раздаются с своего домена — запросов к Google из браузера нет): дисплейный **Montserrat** (ось 100–900, кириллица подтверждена; ближайший к логотипу), текстовый **Onest** (ось 100–900, самый широкий набор субсетов; запасной — Manrope 200–800). Inter/Roboto/системные — запрещены (правило `references/design.md` скилла).
5. Иконки: `lucide-react` + собственные SVG-глифы вредителей и работ (§3.3). Эмодзи в UI запрещены.
6. Анимации: CSS + `motion` (Framer Motion) только для hero-оркестровки, слайдера и раскрытия; `prefers-reduced-motion` уважать.
7. Формы: `react-hook-form` + `zod` (общая схема с сервером из `lib/lead.ts`).
8. Сервер заявок: Route Handler (Node runtime), `nodemailer` для SMTP; Telegram — `fetch` к Bot API без библиотек.
9. Тесты: `node --test` (unit, без зависимостей) и `@playwright/test` (e2e; браузер из `/opt/pw-browsers`, не `playwright install`).
10. Линт/формат: ESLint из шаблона + Prettier. Скрипты `package.json`: `dev`, `build`, `start`, `lint`, `typecheck` (`tsc --noEmit`), `test` (`node --test tests/unit`), `e2e` (`playwright test`), `check` (lint+typecheck+test+build).

Дисплей: Montserrat 900, капс, `letter-spacing -0.02em` для крупных заголовков (как «ДЕЗГАРАНТ» в логотипе), `+0.18em` для мелких капс-подписей (как «ДЕЗИНФЕКЦИЯ • ГАРАНТИЯ • ЧИСТОТА»). Шкала: h1 56/64 (mobile 36), h2 40, h3 28, лид 20, текст 17/1.6, подпись 13 капс. Цифры в статах — Montserrat 800 с `font-variant-numeric: tabular-nums`. ### 3.3 Мотивы и компоненты

1. **Ромб** — контейнер иконок и маркеров списков (квадрат под 45°, диагональный раскол красный/бирюзовый в 2 px обводке). Компонент `Diamond` с вариантами `outline` / `split` / `solid`.
2. **Диагональный раскол** — hero-блоки и разделители секций режутся по диагонали (`clip-path: polygon`), угол одинаков на всех сайтах (~12°).
3. **Контур Оренбургской области** — `OblastOutline` (SVG-path из Natural Earth admin-1, public domain; упростить до ~400 точек), водяной знак в hero и в блоке «зона выезда»; на ДезГаранте подсвечивать районы обслуживания.
4. **Плашка региона** — красный прямоугольник с белым капсом («ОРЕНБУРГСКАЯ ОБЛАСТЬ»), компонент `Badge variant="plate"`.

6. **Фактура** — SVG-noise поверх страницы (opacity ~0.25, `mix-blend-mode: multiply` на светлом / `overlay` на тёмном); на Бриллиант Ремонт — низкоконтрастный фасеточный (low-poly) паттерн.
7. **Глифы** (собственные SVG 24 px, stroke 1.75): таракан, клоп, муравей, блоха, крыса, клещ, плесень, вирус, туман-генератор; для ремонта: мастерок, валик, уровень, плитка, электрика, сантехника, кирпич, ключ. Отрисовать как `components/icons/*.tsx`, единый стиль с lucide.

### 3.4 Три темы

1. **Белые Нити** — тёмная (`black` → `graphite` градиент), белый набор, красный primary, бирюза secondary. Ощущение холдинга: много воздуха, крупная типографика, тонкие линии, ромбы, контур области в hero. Сдержанно.
2. **ДезГарант** — светлая «чистая»: `paper`, чернила `ink`, бирюза primary (кнопки, плашки, иконки), красный — только для срочных CTA («Выезд сегодня») и предупреждений. Щит, перечёркнутые микробы, карточки со срезанным по диагонали углом.
3. **Бриллиант Ремонт** — чёрный + золото по визитке: фон `black`/`graphite`, primary `gold` (кнопки, цифры, линии), светлые секции на `marble` с лёгкой мраморной фактурой (SVG-noise + мягкие прожилки), панели с диагональным срезом как на лицевой стороне визитки, золотая «трещина»-молния с оборота — как разделитель hero и как акцент под заголовками; фасеточный паттерн бриллианта в ультранизком контрасте. Красный и бирюза — только в знаке Белых Нитей в шапке/футере. Крупные фото стен и объектов (до/после), цифры (м², дни, лет гарантии) дисплейным шрифтом. Премиальная отделка.

Вау-приёмы дизайна (использовать дозированно, каждый — с fallback без анимации): hero-раскол, который «дышит» за курсором (граница раскола смещается на 2–3 % к указателю; на тач — нет); сборка логотипа на загрузке (две половины ромба съезжаются, 600 мс, один раз); контур области рисуется `stroke-dashoffset`; счётчики цифр при появлении; появление секций stagger 40 мс; магнитные primary-кнопки (desktop); слайдер до/после на портфолио; мягкий spotlight за курсором на тёмных темах. Не более одного «тяжёлого» эффекта на экран, LCP-элемент без анимаций.

### 3.5 Логотипы в SVG

Исходники — растровые JPEG (`docs/brand/`), прозрачности нет, вектора нет (★ спросить).
